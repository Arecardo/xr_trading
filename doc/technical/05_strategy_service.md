# 策略与组合决策模块技术文档

## 1. 模块目标

策略模块负责按资产类型合成研究结果，组合构建模块将资产观点转换为目标权重与再平衡建议。两者均不直接提交订单。

## 2. 输入

- 投资组合、组合成员与风险预算。
- 技术分析结果。
- 新闻舆情评分。
- 资产类型专属评分。
- 市场环境评分。
- 当前持仓。
- 风控配置中的部分仓位约束。

## 3. 分资产类型评分模型

```text
美股总分 = 技术面 35% + 新闻舆情 25% + 基本面 25% + 市场环境 15%
加密总分 = 技术面 35% + 市场结构与流动性 25% + 网络/供应 20% + 新闻事件 10% + 市场环境 10%
```

配置示例：

```yaml
strategies:
  equity_growth:
    applies_to: [STOCK, ETF]
    technical_weight: 0.35
    sentiment_weight: 0.25
    fundamental_weight: 0.25
    market_regime_weight: 0.15
    buy_threshold: 75
    hold_threshold: 55
    reduce_threshold: 40
```

## 4. 决策规则

| 总分 | 建议 |
| --- | --- |
| `>= 75` | 允许买入或加仓 |
| `55 - 74` | 持有或观察 |
| `40 - 54` | 减仓或禁止新增 |
| `< 40` | 卖出或退出 |

## 5. 市场环境修正

| 市场环境 | 修正 |
| --- | --- |
| risk_on | 不修正或轻微加分 |
| neutral | 降低目标仓位 |
| risk_off | 降低买入评分，禁止新增仓位或只允许减仓 |

## 6. 目标权重与再平衡

建议仓位应受以下限制：

- 单一资产、资产类别和市场的风险预算。
- 保留现金比例不低于 20%。
- 资产相关性、流动性、波动率和交易成本。
- 单笔风险默认不超过账户权益 0.5% 到 1%。

组合构建模块输出全部资产与现金的目标权重，权重合计必须为 1。系统比较当前权重与目标权重生成 `RebalancePlan`，最终是否允许由风控模块决定。

## 7. 输出数据结构

```json
{
  "run_id": "2026-05-31-pre_market-001",
  "portfolio_id": "pf_growth_us_crypto",
  "asset_id": "equity:nasdaq:NVDA",
  "symbol": "NVDA",
  "action": "buy",
  "confidence": 0.78,
  "total_score": 78,
  "target_weight": 0.18,
  "max_loss": 25.0,
  "reason": [
    "technical trend positive",
    "news sentiment positive",
    "market regime risk_on"
  ],
  "strategy_version": "strategy_v0.1.0",
  "created_at": "2026-05-31T08:00:00+08:00"
}
```

## 8. 推荐流程

1. 读取活跃投资组合和成员，排除 `restricted` 与 `blacklist`。
2. 对每个组合资产加载分析结果。
3. 处理缺失评分。
4. 根据权重计算总分。
5. 根据阈值生成 `action`。
6. 根据风险预算、波动率、相关性和市场环境生成目标权重。
7. 对目标权重归一化并保留现金约束。
8. 与当前权重比较，生成再平衡建议和解释原因。
9. 将信号与调仓计划写入可审计存储。

## 9. 缺失数据处理

| 缺失项 | 处理方式 |
| --- | --- |
| 技术指标缺失 | 不允许买入，只允许观察 |
| 新闻缺失 | 舆情分使用中性分 |
| 适用的专属数据缺失 | 按策略降级并明确覆盖率 |
| 市场环境缺失 | 默认为 neutral |

## 10. 测试点

- 权重配置之和不为 1 时拒绝运行。
- `risk_off` 时高分标的也不应直接生成激进买入。
- `restricted` 或 `blacklist` 资产不能生成买入建议。
- 缺少技术指标时不能生成买入建议。
- 每条建议必须包含可读原因。
- 组合目标权重与现金之和必须等于 1。
- 加密资产权重不得突破组合的类别风险预算。
